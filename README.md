# ML-часть: Альфа-Хак "Новостная аналитика для принятия бизнес-решений"

Это стартовый комплект под твою роль (агентная логика + генерация
персонализированных инсайтов), построенный на реальных файлах кейса.

## Что внутри

1. **`client_profiling.py`** — шаг 1 из ТЗ ("проанализируйте данные о
   компании"). Читает три исходных CSV и строит обогащённый профиль
   каждого крупного клиента (REVENUE_COMPANY ≥ 15 млрд ₽ — таких в
   данных **115 из 85 525** компаний, это и есть реальная целевая
   аудитория демо). Признаки: отрасль (укрупнённая), жизненный цикл,
   продукты банка, чувствительности (к ставке, к курсу, к сырью,
   к гос. тендерам...), графовые метрики по платежам (контрагенты,
   входящий/исходящий оборот).
   ```
   python3 client_profiling.py --data-dir ./data --out client_profiles.json
   ```
2. **`client_profiles.json`** — результат запуска на реальных данных
   кейса (115 клиентов), можно сразу отдавать аналитикам/в демо.
3. **`contract_schema.json`** — JSON-контракт для передачи данных между
   этапами пайплайна (требование ТЗ, "Пространство решений", п.6):
   факты / источники / признаки клиента / оценка релевантности / риски
   и возможности / отдельно — позиция банка vs вывод модели /
   трассировка шагов агента.
4. **`agent_pipeline.md`** — архитектура агента: какая задача на какой
   из 6 разрешённых LLM (с учётом бюджета 500₽/день), промпты для
   planning / ranking / generation / self-check.
5. **`demo_output_example.json`** — сквозной пример конечного результата
   на реальном клиенте (U_9250, строительство, Иркутская область,
   есть кредит и лизинг) и реальном материале Приложения 2 ("Ключевая
   ставка ЦБ РФ: ставка без изменения на 14,0%") — ровно в формате
   примера "качественной интерпретации" со слайда 14 ТЗ.

## Что отдать аналитикам как интерфейс данных

- Аналитику 1 (профиль клиента): структура `ClientProfile` в
  `client_profiling.py` — если у него будут более точные признаки
  (например, точная карта ОКВЭД→отрасль вместо моей грубой, или
  доп. графовые метрики), он меняет/дополняет этот файл, выход
  остаётся в формате `client_profiles.json`.
- Аналитику 2 (новости/аналитика банка): на входе моего ranking-шага
  нужен список новостей в виде `{event_id, title, published_at,
  summary_facts[], topic_tags[]}` — максимально близко к блоку
  `event` в `contract_schema.json`. Так же — RAG-индекс по
  Приложению 2 должен отдавать выдержки с привязкой к `source_id`.

## Добавлено после уточнений от организаторов

6. **`call_llm.py`** — готовая обёртка для вызова разрешённых генеративных
   LLM через OpenAI-совместимый API. Как придёт ключ и адрес (endpoint) —
   пропиши их в переменные окружения `ALFA_LLM_API_KEY` /
   `ALFA_LLM_BASE_URL` (инструкция в начале файла) и запускай:
   `python call_llm.py`. Внутри уже есть готовые функции под твои шаги
   пайплайна: `rank_news_for_client`, `generate_interpretation`, `self_check`.
7. **`bank_rag.py`** — поиск по 9 PDF Приложения 2 на **локальных
   эмбеддингах** (multilingual-e5). Организаторы подтвердили: ограничение
   на список моделей касается только генеративных LLM, эмбеддинги можно
   использовать любые и бесплатно — не тратит дневной бюджет 500₽.
   ```
   pip install sentence-transformers pypdf numpy
   python bank_rag.py --pdf-dir ./bank_docs --query "ключевая ставка строительство"
   ```

## Важные уточнения от организаторов (зафиксировано)

- Список из 6 моделей — только для **генеративных** LLM. Локальные модели
  эмбеддингов (multilingual-e5 и т.п.) использовать можно свободно.
- Бюджет 500₽/день — **общий на команду**, один ключ, обновляется в
  00:00 по Москве, остаток не переносится. Ключ перестаёт работать после
  окончания приёма решений.
- Хостинг для демо-прототипа — любой бесплатный провайдер, конкретного
  требования нет.
- Данные по платежам подтверждены: `df_Uid_payment_hack.csv`.
