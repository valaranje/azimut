# azimut -- персонализированная бизнес-аналитика для Альфа-Бизнеса

Хакатон-кейс Альфа-Банка: сервис для руководителей крупного бизнеса (выручка
≥ 15 млрд ₽), который по профилю компании отбирает значимые новости и
объясняет их влияние на эту конкретную компанию, опираясь на аналитику
Альфа-Банка.

Полный разбор условий кейса, реестр требований (критерии C01-C12,
ограничения L01-L06), архитектура, ADR и открытые вопросы к организаторам --
в [`docs/case_analysis.md`](docs/case_analysis.md). Этот README -- только
про то, как запустить и проверить то, что уже есть.

## Требования к окружению

- Python 3.11+ (venv)
- Tesseract OCR (бинарник, отдельно от pip) -- только для сборки RAG-индекса
  по PDF банка, см. шаг 3 ниже
- Файл `.env` с ключом доступа к LLM (выдаёт организатор) -- см. `.env.example`

## Установка

```bash
python -m venv venv
# Windows:
venv\Scripts\activate
# macOS/Linux:
source venv/bin/activate

pip install -r requirements.txt
cp .env.example .env   # дальше открыть .env и вписать ALFA_LLM_API_KEY / ALFA_LLM_BASE_URL
```

## Запуск по шагам (сценарий проверки)

### 1. Профили клиентов (K4)

Уже лежат в `client_profiles.json` (115 компаний с выручкой ≥ 15 млрд ₽).
Пересобрать из сырых CSV заново:

```bash
python client_profiling.py --out client_profiles.json
```

### 2. Новости (K1)

В `news.db` уже есть собранные новости. Обновить свежими:

```bash
python news_parser.py --db news.db --days 7
python news_stats.py --db news.db   # глазами проверить, что теги разумные
```

### 3. RAG-индекс по аналитике банка (K3) -- пока не выполнено

```bash
pip install sentence-transformers pymupdf pytesseract numpy
# + поставить сам Tesseract: https://github.com/UB-Mannheim/tesseract/wiki
#   (отметить галочку Russian language data при установке)

python bank_rag.py --pdf-dir ./bank_docs --query "ключевая ставка строительство"
# первый вызов с --pdf-dir построит bank_rag_index.json (это долго: OCR 9 PDF)
```

Без этого шага `agent.py` всё равно работает -- просто без выдержек из
аналитики банка (см. `default_rag_search` в `agent.py`: при отсутствии
индекса агент продолжает работу с warning в логе).

### 4. Проверить ключ LLM

```bash
python call_llm.py --ping --all
```

Если видишь `model not found` -- поправь id модели в `.env`
(`ALFA_MODEL_...`), организатор присылает точные названия отдельно.

### 5. Прогнать агентный цикл на одном клиенте (K7, вертикальный срез)

```bash
# без LLM -- только проверить, что ранжирование находит кандидатов:
python agent.py --client U_9250 --no-llm

# полный прогон с генерацией интерпретации:
python agent.py --client U_9250 --out insights.json
```

Результат -- `insights.json` по схеме `contract_schema.json` (пример
того, что должно получиться -- `demo_output_example.json`).
