# alfa — сводный документ по кейсу Альфа-Банка

**Версия:** v0.1 (черновик) · **Дата:** 25.10.2026 · **Основание:** последовательный разбор 10 файлов проекта (бизнес-контекст, целевая аудитория, постановка задачи, критерии успеха, ограничения, пространство решений, шесть вопросов интерпретации, Приложения 1–3).

## 0. Как читать документ

Метки показывают происхождение каждого утверждения. Это нужно, чтобы не принять мои предложения за требования кейса.

| Метка | Значение |
|---|---|
| **[КЕЙС]** | Требование, ограничение или факт, прямо написанный в файлах кейса |
| **[ВЫВОД]** | Логическое следствие из файлов кейса, проверяемое по тексту |
| **[ПРЕДЛОЖЕНИЕ]** | Предложение по решению. **Командой не принято**, пока не записано в разделе 6 со статусом «принято» |
| **[ВОПРОС]** | То, что нельзя определить по файлам; нужно уточнить у организаторов или в репозитории |

**Ограничения разбора (важно):**
1. Нумерация критериев (01–12), ограничений (01–06) и шести вопросов интерпретации восстановлена по порядку текстовых блоков, потому что файлы извлечены из вёрстки презентации. **Сверить с оригиналом слайдов.**
2. Файлы данных (CSV) и тексты материалов банка не просматривались: есть только описания полей и названия материалов.
3. Репозиторий не был доступен; история коммитов не изучалась.
4. Характеристики разрешённых моделей (контекст, цена, поддержка JSON) не проверялись.

## 1. Резюме

1. **Продукт:** сервис для руководителей крупного бизнеса (выручка свыше 15 млрд ₽), который определяет профиль компании, отбирает значимые события и объясняет их влияние на **эту** компанию с опорой на внешние новости и аналитику Альфа-Банка. [КЕЙС]
2. **Не лента и не пересказ.** Ценность в интерпретации: что произошло, почему важно этой компании, какие последствия, какие действия, как оценивает банк, на чём основан вывод. [КЕЙС]
3. **Данные обезличены**, поэтому персонализация строится по атрибутам (отрасль, продукты, внешнеэкономика, структура платежей), а не по названиям компаний. [ВЫВОД]
4. **Позиция банка только макро** (ставка, инфляция, облигации, золото, сырьё, рынок труда, потребление, ВВП). По темам без материалов система должна честно сказать «прямой позиции банка нет». [ВЫВОД]
5. **Агентная логика обязательна** (планирование, инструменты, общий контекст, самопроверка), но **готовые** автономные агенты и мультиагентные системы как основа запрещены. Цикл пишет команда. [КЕЙС]
6. **Только 6 разрешённых моделей**, бюджет ограничен (500 ₽, дневной лимит токенов; трактовка неясна). [КЕЙС]
7. **Три сквозных механизма**, закрывающие большую часть критериев: единая схема утверждения (источник, происхождение, достоверность), единый журнал вызовов (трассировка, безопасность, бюджет), шаблон из шести вопросов (структура карточки, чек-лист самопроверки, рубрика оценки). [ПРЕДЛОЖЕНИЕ]
8. **Главные риски:** бюджет LLM, воспроизводимость запуска у жюри, неопределённости правил (библиотеки, эмбеддинги, ключ, публикация данных), отсутствие корпуса новостей в кейсе. [ВЫВОД]

## 2. Глоссарий (единые термины)

| Термин | Определение | Статус |
|---|---|---|
| **Компания** | Юрлицо (`SYNTHETIC_U`) или группа (`GROUP_ID`). Базовая единица анализа: юрлицо | [ПРЕДЛОЖЕНИЕ] |
| **Клиент банка** | Договорная сторона банка; в данных `CL_TYPE` (действующий / потенциальный) | [КЕЙС] |
| **Пользователь** | Человек с ролью (собственник, CEO, CFO, казначей, главбух, иной) и доступом к интернет-банку. Одна компания имеет несколько пользователей | [КЕЙС] |
| **Профиль компании** | Структурированный набор признаков (поле, значение, источник, происхождение, уверенность) | [ПРЕДЛОЖЕНИЕ] |
| **Бизнес-контекст** | Смысловая интерпретация профиля: положение в отрасли, чувствительность к факторам | [ПРЕДЛОЖЕНИЕ] |
| **Релевантность** | Степень связи события с профилем компании | [ПРЕДЛОЖЕНИЕ] |
| **Значимость** | Релевантность × масштаб влияния × срочность; по ней ранжируется сводка | [ПРЕДЛОЖЕНИЕ] |
| **Сводка** | Ранжированный список карточек для выбранной компании и роли | [ПРЕДЛОЖЕНИЕ] |
| **Карточка** | Формат выдачи по одному событию; содержание карточки = «качественная интерпретация» из шести вопросов (синоним в постановке: «бизнес-инсайт») | [ПРЕДЛОЖЕНИЕ] |
| **Позиция банка** | Содержание аналитических материалов Центра макроэкономических исследований Альфа-Банка из кейса (Приложение 2) | [ПРЕДЛОЖЕНИЕ] |
| **Контекст** | Ближайшая макрорамка без прямой позиции банка по теме; всегда с меткой «контекст» | [ПРЕДЛОЖЕНИЕ] |
| **Вывод модели** | Всё, что получено рассуждением модели и не является фактом источника или позицией банка | [ВЫВОД] |
| **Агентная логика** | Требуемый кейсом собственный контролируемый цикл: план → инструменты → общий контекст → самопроверка и коррекция, с ограниченным числом шагов | [КЕЙС] + [ПРЕДЛОЖЕНИЕ] |
| **Автономный AI-агент / готовая мультиагентная система** | Готовые внешние решения; запрещены как основной компонент | [КЕЙС] |
| **Экспозиция** | Чувствительность компании к макрофактору (ставка, курс, сырьё, труд, потребление и т.д.) | [ПРЕДЛОЖЕНИЕ] |
| **Происхождение (`origin`)** | Откуда утверждение: внешний источник / аналитика банка / данные клиента / модель | [ПРЕДЛОЖЕНИЕ] |
| **Достоверность (`certainty`)** | Статус утверждения: факт / вывод / гипотеза | [ПРЕДЛОЖЕНИЕ] |

## 3. Реестр требований кейса

### 3.1 Задачи (постановка задачи)

| ID | Требование | Источник |
|---|---|---|
| T1 | Проанализировать данные о компании или группе: отрасль, положение, доля рынка, виды деятельности, масштаб и другие признаки | Постановка |
| T2 | Механизм персонализированного отбора и ранжирования новостей по бизнес-контексту | Постановка |
| T3 | Персонализированная интерпретация значимых событий на основе признаков из T1 с учётом аналитики банка | Постановка |
| T4 | Парсер внешних новостей и аналитических материалов банка; классификация и выделение ключевой информации | Постановка |
| T5 | Пользовательский сценарий и результат в интерфейсе интернет-банка Альфа-Бизнеса; факты, аналитика и интерпретация подаются понятно и последовательно | Постановка |

### 3.2 Агентная логика

| ID | Требование | Источник |
|---|---|---|
| A1 | Планирование: определить нужные данные и источники, сформировать последовательность шагов | Постановка |
| A2 | Работа с инструментами: профиль клиента, новости, аналитика банка, поиск/RAG и др. инструменты команды | Постановка |
| A3 | Контекст: результаты предыдущих шагов используются в последующих, единый контекст компании и события | Постановка |
| A4 | Самопроверка и адаптация: оценка полноты, непротиворечивости, обоснованности; повторный поиск, уточнение данных, коррекция шагов | Постановка |

### 3.3 Критерии успеха (нумерация восстановлена)

| ID | Суть критерия |
|---|---|
| C01 | Определяет бизнес-контекст по данным и отбирает события, значимые для конкретного клиента |
| C02 | Содержательная интерпретация: последствия, риски, возможности, несколько факторов; не пересказ и не очевидное следствие из одной новости |
| C03 | Использует аналитику и позицию банка из материалов кейса; пользователь видит, какие выводы от банка, а какие от AI |

| C05 | Устойчивое качество на ранее не показанных новостях; независимость от заготовленных сценариев |

| C09 | На главном экране интернет-приложения Альфа-Бизнеса есть заметная и постоянно доступная точка входа |
| C10 | Интерфейс взаимодействия: уточняющий вопрос, данные в другом разрезе, переход к первоисточнику |
| C11 | Агентная логика: самостоятельное формирование и выполнение шагов, обращение к источникам и инструментам, коррекция при недостаточности или противоречивости данных |
| C12 | Трассируемость: можно восстановить источники, признаки компании, повлиявшие на вывод, и результаты существенных промежуточных этапов |

### 3.4 Ограничения (нумерация восстановлена)

| ID | Ограничение |
|---|---|
| L01 | Не обычная новостная лента и не ИИ-пересказ; ценность в глубокой интерпретации с контекстом клиента (в источнике дан пример со ставкой 14%) |
| L02 | Аналитика и экспертное мнение банка: заметная часть ценности, влияет на выводы |

| L05 | Корректная работа с неполными, неоднозначными и зашумлёнными данными |
| L06 | Безопасность AI-компонентов: права доступа, защита чувствительных данных, контроль и журналирование обращений к инструментам, ограничения на небезопасные действия. Для прототипа достаточно обоснованно описать и показать место в архитектуре |

## 4. Предлагаемая архитектура (все пункты [ПРЕДЛОЖЕНИЕ])

### 4.1 Компоненты

| ID | Компонент | Назначение |
|---|---|---|
| K1 | Парсер и ingestion | Сбор новостей из внешних источников; загрузка материалов банка; метаданные, URL, хеш; снимок корпуса |
| K2 | Обогащение статьи (уровень статьи, кэш) | Классификация, теги (отрасль, регион, макрофактор), ключевые факты, риски и возможности «вообще» |
| K3 | Реестр позиций банка (RAG) | Тезисы, направление, прогноз, горизонт, факторы, дата актуальности, указатель на фрагмент |
| K4 | Профиль компании | Правила + граф платежей и групп; поля с источником, происхождением, уверенностью |
| K5 | Матрица экспозиций (конфиг) | Признак компании → чувствительность к макрофактору; помечена как допущение команды |
| K6 | Сопоставление и ранжирование | Релевантность и значимость по профилю и роли |
| K7 | Агентный цикл | План → вызов инструментов из белого списка → общий контекст → самопроверка → коррекция; лимит шагов и бюджета |
| K8 | Генератор карточки | Интерпретация по шести вопросам, утверждения по схеме из 4.2 |
| K9 | Журнал вызовов и трассировка | Запись шагов, источников, использованных признаков, токенов; основа для аудита и воспроизведения |
| K10 | Интерфейс | Макет Альфа-Бизнеса: точка входа на главном экране, выбор клиента и роли, сводка, карточка, диалог, переход к источнику |
| K11 | Оценка и мониторинг | Золотые карточки, отложенная выборка, метрики, обратная связь |
| K12 | Безопасность и доступ | Роли, минимизация данных, защита от инъекций через новости, запрет действий с побочными эффектами |
| K13 | Упаковка | Docker, lock-файлы, конфигурация, README, THIRD_PARTY_NOTICES, синтетические данные |

### 4.2 Схема утверждения (claim) — обмен между компонентами

| Поле | Смысл |
|---|---|
| `id` | Идентификатор утверждения |
| `text` | Формулировка |
| `origin` | `external_source` / `bank_analytics` / `client_data` / `model` |
| `certainty` | `fact` / `inference` / `hypothesis` |
| `evidence[]` | Источники: `source_id`, фрагмент или позиция, дата актуальности |
| `company_features[]` | Поля профиля, на которые опирается утверждение (с исходным столбцом данных) |
| `relevance` | Компоненты оценки релевантности |
| `impact` | `risk` / `opportunity` / `neutral`, сила, горизонт |
| `confidence` | Уверенность и причины её снижения |
| `verification` | Результат проверки (детерминированной и/или моделью-ревизором) |

Одна схема закрывает C03, C04, C12, I1, I5, I6 и соответствует S5.

## Приложение B. Блоки профиля компании

| Блок | Поля данных |
|---|---|

| Масштаб | `REVENUE_COMPANY`, численность (ФНС, СПАРК) |
| Отрасль | `MAINOKVED_CODE`, `MAINOKVED_NAME` |

Для каждого поля: значение, исходный столбец, происхождение (из данных / вычислено / допущение), уверенность. Продукты и платежи видны только в рамках Альфа-Банка и набора; формулировки «в продуктах Альфа-Банка», «среди клиентов набора».

## Приложение C. Что нельзя утверждать (честные формулировки)

| Нельзя | Можно |
|---|---|
| «Доля рынка компании — X%» | «Доля среди клиентов банка по отрасли и региону» |
| «У компании нет долга» | «Нет кредитных продуктов Альфа-Банка» |
| «Компания присутствует в регионе X» | «Компания зарегистрирована в регионе X» |

| «Позиция банка по курсу рубля — …» | «Прямой позиции банка по теме в материалах нет; контекст: …» |
| Числа без источника | Только числа, найденные в источнике |

## Приложение D. Чек-лист data audit (без кода)

1. Размеры таблиц, доля пропусков по каждому полю.
2. Распределение выручки: сколько компаний выше 15 млрд ₽; единицы и год.
3. Уникальные значения градаций возраста и численности; расхождения ФНС и СПАРК.
4. Гранулярность ОКВЭД: длина кода, число классов; согласованность кода и названия.
5. Доли `CL_TYPE`, каждого флага продукта, `FTS_FLAG`; список стран ФТС.
6. `GROUP_ID`: размеры групп, доля компаний без группы.
7. Платежи: `PAYER` и `BENEFICIARY`, которых нет в таблице юрлиц; самоплатежи; дубли пар; распределения сумм и степеней.
8. Физлица: число компаний на лицо и лиц на компанию.
9. `NEGATIVEMARK`: значения и их согласованность с описанием.

## Приложение E. Чек-лист самопроверки карточки (по шести вопросам)

| Вопрос | Проверка |
|---|---|
| I1 | Факты, участники, сроки, причины есть; причина без источника помечена гипотезой; числа и даты найдены в источнике |
| I2 | Названы конкретные признаки профиля; нет утверждений вне данных (см. Приложение C) |
| I3 | Риск и/или возможность, сила, горизонт, условия; нет выдуманных процентов |
| I4 | Действие привязано к признаку профиля; проходит тест «подставь другого клиента»; допустимо «действий не требуется» |
| I5 | Метки `origin`; дата материала банка; при отсутствии позиции — явное сообщение |
| I6 | У каждого утверждения есть источник и признаки; журнал вызовов восстанавливает цепочку |
